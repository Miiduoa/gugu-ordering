# 上線驗收檢查表

只有全部完成，才可把系統張貼成店家正式點餐入口。不能用「程式能跑」代替營運驗收。

## 店家資料

- [ ] 店家知道此服務的用途，已同意使用店名、地址、營業資料與正式點餐流程。
- [ ] 每一道正式餐點、自取價格、加價、飯量、辣度、可供應日期都由店家核對。
- [ ] 沒有把外送平台價當成自取價；沒有虛構卡路里、營養、過敏原或菜色照片。
- [ ] 營業日、午晚餐時段、公休、準備時間、時段容量、每日剩餘份數皆確認。
- [ ] 明確告知「需等店家接單」及逾時取消規則；客服聯絡方式可用。

## 伺服器與權限

- [ ] 正式 live 使用新的持久化資料庫，無測試訂單或範例菜單。
- [ ] 網域為店家控制；店外行動網路可用 HTTPS 連線，沒有 mixed content。
- [ ] Cookie Secure、HttpOnly、SameSite、CSRF、Origin、Host 及反向代理來源 IP 實際驗證。
- [ ] 應用 8000 port 不直接公開；主機不會自動休眠。
- [ ] 管理者更改隨機密碼；店員一人一個角色帳號；舊憑證檔已刪除。
- [ ] 對目標瀏覽器執行原生網路測試，包含實機 iPhone Safari、Mac Safari／Chrome。

## 接單與現場

- [ ] 手機建立訂單，店家另一台裝置讀到同一筆；明天待接單亦會提醒。
- [ ] 連點、斷線重試、售完、時段額滿、價格改變及同事同時操作均正確拒絕或重播。
- [ ] 接單→製作→備妥→實際收現→交付，店家與顧客都顯示一致狀態。
- [ ] 製作前取消回補，製作後取消不回補；退款只記已實際退還的現金。
- [ ] 單純「已送出」及取餐號碼不會被當成已付款證明。
- [ ] 看板不露姓名電話；實體印表機列印測試完成，未把取餐單當發票。
- [ ] 店員知道背景／鎖屏不保證聲音通知；有指定接單人員和網路中斷備案。

## 資料與營運

- [ ] 店家確認個資告知、保存天數、查詢／刪除聯絡流程；必要時由適當專業人員確認。
- [ ] 已設定備份排程、加密／異地副本、保留期限及失敗通知。
- [ ] 在另一份資料庫實際還原成功，知道可容忍的資料遺失時間。
- [ ] 關店報表與實際現金、退款、未取餐、其他通路收入分開核對。
- [ ] 先少量試營運，記錄漏單、接單秒數、製作逾時與現場操作錯誤，再調整容量。
