# 穀穀點餐系統

給單店外帶自取使用的點餐、接單與取餐工作台。顧客免註冊，店員各自登入。付款範圍是**到店現金收款紀錄**，不是線上金流。

**版本 1.0.0｜2026-10-08｜店家提案／測試版本，未經店家正式驗收。**

此套程式以「穀穀健康廚房－台中學府總店」為提案對象。店家名稱及地址參考公開資訊；範例售價、庫存、規格及文字說明不是店家已確認的資料。測試訂單不會送到真實店家。不要放入真實個資，不要把展示連結張貼成正式點餐入口。

## Render 隔離測試

雲端入口使用 `app.cloud:app`，啟動時強制 `APP_MODE=demo`，拒絕改成正式接單模式。全站需先輸入測試入口密碼，店家後台另需登入。兩組密碼均以 Argon2id 雜湊保存在 Render 環境變數，沒有寫進原始碼。

此服務使用免費測試機器與暫存 SQLite，重新部署、重啟或休眠後，測試資料可能清除。請勿填入真實顧客個資。帳號初始值由部署環境提供，資料庫重建後會恢復初始測試帳號。正式營業需另建持久資料庫、備份、監控並完成店家驗收。

- 核心回歸：`python -m pytest -q`
- 雲端存取保護：`python scripts/check_staging.py`
- 全站健康檢查：`GET /api/health`

## 先看畫面，不安裝

用電腦瀏覽器開啟 `preview/index.html`。可完成選餐、預約、送單，再從「店家工作台」選擇體驗身分，依序操作接單、製作、取餐及收款。此單檔離線展示只使用目前瀏覽器的記憶體／本機儲存；不會跨裝置同步，也沒有真正的帳號安全邊界。瀏覽器拒絕本機儲存時，重新開啟可能清空資料。切換到隔天會重設展示測試資料。

手機聊天軟體的 HTML 快速預覽不一定執行 JavaScript。這不是程式壞掉，請在 Mac 的 Safari／Chrome 開啟檔案，或啟動下方完整後端。

## Mac 啟動完整系統

需要 Python 3.11 以上；已在 Python 3.13.5 測試。第一次安裝套件需要網路。先解壓縮 ZIP，在終端機輸入 `cd `（後面一個空格），把解壓縮的 `gugu-ordering` 資料夾拖進終端機，按 Enter，再執行：

```bash
bash start.command
```

程式會建立獨立 `.venv`、安裝套件、建立本機資料庫，以及產生隨機管理者密碼。**沒有共用預設密碼**。密碼顯示在終端機，也存於 `data/local-access.txt`；登入後請更改密碼，再刪除該檔案。

顧客點餐：`http://127.0.0.1:8000`  
店家工作台：`http://127.0.0.1:8000/staff/`  
取餐看板：`http://127.0.0.1:8000/display/`

這三個本機網址只供目前電腦使用，不能當成店外手機點餐網址。按 Control+C 停止；資料留在 `data/`，下次啟動會保留。Mac 關機、休眠或關閉伺服器，其他人就不能使用。因此正式營運應採持續開機的主機，配置 HTTPS 與備份，而不是讓你的上課筆電充當正式伺服器。

金額由後端使用整數新台幣計算。下單會在同一交易內檢查售價版本、菜單狀態、時段容量、商品庫存及重複送單識別碼。改價不會改掉已成立訂單的價格。開始製作後取消，不會把已耗用的份數灌回庫存。

## 三件重要的營運決定

**只做外帶自取，不收線上付款。** 先讓店家順利接單、做餐、收錢、交付，而不是一開始增加配送與對帳負擔。現金紀錄需店員勾選確認，程式不會自動扣款或退款。

**正式模式只在設定的營業時間接收新單。** 可在營業中預約未來取餐日；休息時間不收無人看管的訂單。所有新單都需要店家確認，超過接單期限自動取消。測試模式改用全天測試時段，因此不代表真實營業時間。

**提示音不是手機推播。** 店家工作台需保持前景、開啟提示音，且避免裝置休眠。顧客完成通知是查詢頁更新；目前沒有 LINE、簡訊、電子郵件或鎖定畫面推播。

## 尚未接入／不包含

LINE 官方帳號及登入、LINE Pay／綠界等金流、信用卡、簡訊 OTP、配送媒合、電子發票、POS 雙向同步、熱感印表機自動列印及食材 BOM。店家尚未授權或驗收，也不會收到測試訂單。列印的只是取餐憑單，不是統一發票。

單店、單台主機、單一持久化 SQLite 資料庫；不是多分店 SaaS 或無限水平擴充服務。禁止把資料庫放在臨時檔案系統、網路共享磁碟、iCloud 同步中的執行目錄，或多台應用伺服器共用。

## 檔案與操作

`app/` 後端與規則；`static/` 共用前端；`preview/` 單檔展示；`tests/` 回歸測試；`scripts/` 瀏覽器驗證與備份；`docs/` 店家操作、部署、架構、驗收與資料來源。

```bash
# 已有虛擬環境時
.venv/bin/python manage.py check
.venv/bin/python manage.py backup
.venv/bin/python manage.py reset-password --username owner

# 開發測試
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/python -m playwright install chromium
.venv/bin/python scripts/browser_check.py
```

正式部署請閱讀 `docs/部署與備份.md`。**不要直接把測試資料庫改成 live**；程式會阻擋這種切換。正式環境必須使用新的資料目錄，由店家建立確認過的菜單，才開放訂購。
