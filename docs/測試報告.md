## 後端覆蓋範圍

訂單驗證包含整數份數、必選規格、加價、售價版本、時間、停業、公休、庫存、時段容量與同品項多列合併檢查。金額由後端重算，不能信任客戶端傳來的總價。

交易與併發測試實際包含：20 個請求搶最後 5 份，只有 5 筆成功；20 個請求搶容量 6 份的時段，只有 6 筆成功；12 個使用相同重複送單識別碼的請求，只建立 1 筆訂單。這些是小規模正確性測試，不是持續高流量效能測試。

營運測試包含接單、製作、出餐、現金確認、交付、拒單、取消、逾時、未取餐和退款。檢查接單前取消只回補一次庫存、製作後不回補已耗用份數、收款與交付分開、實際退現需確認，以及報表保留收入與退款的獨立紀錄。

安全及資料測試包含角色權限、工作階段撤銷、CSRF、來源／主機檢查、登入與下單限流、請求大小、看板不顯示個資、憑單字串跳脫、CSV 不匯出個資及任意備註、到期匿名化、備份完整性。也實際執行管理指令的建立帳號、備份與還原，並檢查測試／正式資料庫不得混用。

未來日期待接單清單也有回歸測試，避免預約單只因不在今天畫面而漏接。正式模式在非營業期間拒絕新單；測試模式使用全天測試時段。

## 介面整合的 9 項檢查

1. 模擬後端已存單、回應卻遺失；在同一表單重試仍沿用原筆識別碼，不產生第二筆。
2. 手機尺寸畫面完成選餐、客製、購物車、預約、送單及私人查詢。
3. 獨立店家瀏覽器讀取另一顧客瀏覽器建立的資料庫訂單。
4. 店家接單、開始製作、完成出餐後，顧客查詢畫面自動更新。
5. 確認現金收款並交付後，顧客畫面更新為已取餐。
6. 菜單庫存、報表、營業設定、人員權限、操作紀錄正常載入。
7. 重新載入後仍可查詢原資料庫訂單。
8. 獨立單檔 HTML 展示可走完點餐、接單與收款流程。
9. 無未處理的 JavaScript 執行錯誤。

### 測試橋接的限制

交付環境的 Chromium 有管理政策，不能進行一般網頁網址導覽。因此本次使用 `about:blank` 渲染實際前端，並以 Python HTTP 橋接連到獨立啟動的真實 uvicorn API；不是把後端結果直接假造到畫面。不同畫面使用各自的 HTTP 工作階段，訂單寫入真正的測試 SQLite 資料庫。沒有移除或修改瀏覽器政策。

此方法能驗證介面互動、API 請求／回應、資料持久化及畫面同步，**不能替代原生瀏覽器 Cookie、HTTPS、CSP 執行、反向代理、真實手機 Safari 及實際網路環境的測試**。正式上線前必須再進行正常網址下的完整驗收。

一般開發環境可執行 `python scripts/browser_check.py` 使用正常瀏覽器流程；`BROWSER_HTTP_BRIDGE=1` 只供上述受限測試環境使用，並非正式系統的一部分。正常網址模式尚未在此環境成功執行，不列為已通過。

## 本輪修正的主要問題

回應遺失後重試原筆訂單，不重新產生識別碼；製作後取消不回補耗用庫存；未來日期待接單加上提醒與跳轉；正式模式在無人接單的休息時段拒收新單；測試／正式資料庫加上不可混用檢查；密碼雜湊驗證限制並行數，降低同時登入的記憶體耗用。以上對應的後端或介面回歸檢查已通過。
