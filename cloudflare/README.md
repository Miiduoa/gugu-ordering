# 穀穀健康廚房｜學府總店點餐系統

原生 Cloudflare Worker、獨立 D1、靜態餐點照片，適用單店外帶自取與到店現金收款。不連接其他專案，不使用 Render 暫存磁碟。這個子目錄可單獨部署。

[部署到自己的 Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/Miiduoa/gugu-ordering/tree/cloudflare-production/cloudflare)

**部署設定與已公開上線是兩回事。** 只有 Cloudflare 回報部署成功、資料庫健康、網頁驗收通過，且完成帳號領取與店家啟用後，才可作為真實點餐入口。未領取的臨時 Cloudflare 帳號有期限，不可用來保留正式訂單。

## 初次使用

部署流程只需 Workers Free 與 D1 Free。不要新增 R2、付費 Workers、付費網域或其他計費產品。本程式不包含購買或升級指令，額度不足時應停止接單而不是默默改成付費。

D1 綁定名稱為 `DB`，未指定既有帳號或資料庫 ID；由 Cloudflare 建立獨立資料庫。第一次 API 啟動會在單一 D1 transaction 建立結構與菜單，之後不再重新灌入。網頁靜態檔與照片使用 Workers Assets；不經 Worker 的靜態資產不耗用 API 請求額度。

開啟 `/staff/`，輸入私下交付的一次性啟用碼，設定自己的帳號與至少 12 字元密碼。程式只有啟用碼的 SHA-256 雜湊，沒有公開預設帳密，也不需要 Cloudflare API Token 交給顧客或前端。

後台核對實際菜單、照片、營業日與時段，填入今天剩餘可售份數，再按「開始今天接單」。首次需店長確認。初始庫存為零、接單關閉；這是新店啟用保護，不是模擬下單。

## 顧客與店家

顧客 `/`：餐點實拍、餐盒與單點主菜、飯量替換、打拋豬辣度、數量、取餐時間、自備餐盒折扣、附湯需求、備註與隱私同意。免註冊，到店付現。

`/order/…#…` 是私人訂單連結，查詢權杖在 fragment，不放 URL query。瀏覽器只在呼叫自己的訂單 API 時傳送權杖。訂單需由店員確認；尚未接單可取消。未確認網路結果時沿用原識別碼重試，避免重複下單；同一分頁重新整理可恢復未確認送單。

`/staff/`：接單、拒單、製作、出餐、確認收款與交付、取消、退款紀錄、憑單列印、報表與 CSV、餐點新增／下架／照片／售價／庫存、營業設定、店員建立／停用／重設密碼，以及修改自己的帳號與密碼。密碼或帳號修改會撤銷該帳號所有舊登入。廚房只能更改製作狀態，看不到手機，也不能收款。

`/display/`：僅顯示取餐號碼及狀態，不顯示客人姓名與手機。

## 不是只靠畫面檢查的規則

金額以整數新台幣計算，售價由伺服器決定。餐盒與單點主菜共用庫存。訂單、時段容量、庫存、菜單版本及防重複識別碼都在 D1 batch transaction 內檢查；失敗會一起回滾。SQL trigger 負責扣庫存；尚未製作取消才歸還可售份數。管理者編輯庫存也檢查數量快照，避免蓋掉剛成立的訂單。

現金已收款和已交付分開記錄。退款只記錄實際現金退款，不會轉帳；先結束或取消訂單，再由店長登記退款。API 包含未取餐狀態；前台主要操作為取消、製作與交付。

工作台須保持前景，每次在線回報有 90 秒有效期；離線、鎖定、休眠或網路中斷太久，停止接受新單。這不能取代櫃台責任：提示音不是手機背景推播。請固定使用店內平板／電腦，必要時回電話或現場接單。已成立訂單仍保留，待店員重新連線處理。每日開單至當日最後營業時段結束，不會自動翌日開單。

每單最多 30 份、最多 20 筆明細；同一手機最多 3 筆待完成訂單，未結束總量上限 900 筆。工作台最多顯示 1,000 筆且優先待處理；超過時明確提示，歷史以備份／報表查核。這是單店系統，不是多店或無限容量 SaaS。

## 餐點資料與圖片

菜單依使用者提供的學府總店照片轉錄：12 款餐盒、其中 11 款可單點主菜、3 款季節湯與 5 款加點，共 31 個購買規格。11 張原始菜單餐盒照片對應 12 款餐盒，醬燒豬／牛五花共用照片且在詳情標示。原始裁切照片約 115 px，沒有假裝成高解析原圖或以生成照片冒充。

自備餐盒每個折 2 元，單點除外。飯換菜或地瓜不加價（所提供菜單未標示加價）。季節湯預設下架，需店家確認供應後開啟。每日限量不代表知道庫存：實際份數由店家填。

店家可用手機選擇 JPEG／PNG／WebP。瀏覽器先重新編碼、去除中繼資料並縮圖，伺服器驗證 WebP 結構與尺寸後儲存在 D1。每張最多 96 KiB，總上傳最多 200 張／20 MiB，不需要 R2 計費訂閱。未提供照片的湯與加點清楚標示「尚未提供照片」。餐點照片與商標不授予第三方再利用權。

## 資料保護與維運

TLS、HttpOnly／Secure／SameSite=Strict Cookie、CSRF、同源檢查、角色驗證、登入速率限制、限長輸入。密碼由瀏覽器 PBKDF2-SHA256 600,000 次，再由伺服器 SHA-256 儲存驗證值；原密碼與驗證值不得寫入日誌。這是本專案驗證協定，尚未經外部資安稽核。

後台備份需重新輸入密碼，單次 D1 transaction 取得一致快照；不包含 sessions。備份含個資與帳號雜湊，應存於受保護位置，不要公開上傳。網頁備份每表最多 10,000 列、總 JSON 最多 25 MB；接近額度或 CPU 上限請改用 Cloudflare D1 官方 SQL 匯出，不能假設任何大小都能從瀏覽器下載。

Cloudflare D1 Time Travel 是額外復原途徑（Free 的還原視窗依官方方案，目前為 7 天），不能取代自行保存備份。`npm run backup:sql` 匯出完整 SQL；在自己授權的終端機執行。

網頁 JSON 還原工具：`node scripts/restore.mjs backup.json restored.sql`，**只能還原到新建的空白隔離資料庫**。工具保留庫存快照、不重複扣庫存、清空登入，並將店家設為暫停。原資料庫不得直接覆寫；驗證訂單與收款後才切換綁定。SQLite 回歸測試有實際驗證還原，但不能把本機測試說成已操作雲端災難復原。

每日排程移除超過保留期限的已結束訂單個資，預設 30 天。手動備份由店家另行管理。暫時帳號的資源與資料若未如期領取會被平台刪除，務必先領取再營業。

## 開發與驗證

```sh
npm install
npm run build
npm test
python -m pip install -r requirements-test.txt
python -m playwright install chromium
npm run test:browser
```

單元與交易測試使用 SQLite 的 D1 介面實作；瀏覽器驗收另以 Wrangler / workerd 真實本機 D1 執行。CI 會保存測試結果與畫面，不把未通過的測試報成成功。啟用碼不參與 CI，測試使用獨立測試碼與全新資料目錄。

## 尚未涵蓋

LINE／簡訊推播、線上付款、電子發票、外送媒合、POS 同步、店員實機長時間營業驗收與外部安全稽核。瀏覽器列印是取餐憑單，不是發票；不能保證所有熱感印表機。

免費資源有容量、每日讀寫與 CPU 限制，沒有付費 SLA。額度用盡可能暫停 API，必須保留電話／現場接單；不承諾永久免費、無限流量或零故障。
